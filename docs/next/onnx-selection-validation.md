# ONNX 六图选型：三机校准与验收

日期：2026-10-18。当前正式阈值：**0.8**，按用户要求简化，GPU 推理耗时需至少降低 20%。
以下三机数据及中点计算保留为历史校准记录，当时使用的验收阈值为 0.69639683662382。

每台设备五个独立校准进程、三个独立验收进程，共 24 个新进程。
每个进程的 CPU/GPU 各运行一次预热和两次计时，输入为相同的六张中英数字图片。
使用 PP-OCRv6 small rec、DML 1.24.4、CPU 4/1 线程和生产预处理。
CPU/GPU 解码结果全部一致，无失败或超时。

比值为 GPU 两次正式推理累计时间 / CPU 两次正式推理累计时间；越小表示 GPU 越快。
会话加载、预热、解释器启动、文件读写和结果检查不进入这个比值。
校准交替执行顺序，验收按生产流程固定 CPU 先、GPU 后。

## 历史校准阈值计算

- L = Ultra 5 与 MAX395 全部有效比值的最大值 = `0.5508244759786391`。
- U = i7 最小有效比值与 1.0 的较小值 = `0.841969197269001`。
- T = `(L + U) / 2` = `0.69639683662382`。

i7 校准中有一次比值为 0.841969，其余为 1.54–1.67；保留全部记录，没有剔除这一测量。
三个后续独立验收均选择 CPU。阈值不依赖 CPU 名称或 GPU 型号匹配。
正常设备发现另已确认 i7 主机的首选为 RTX 3060 Ti、普通 DXGI 索引 1；
这台主机在应用正常 auto 模式下仍遵从独显优先，UHD 770 只由校准工具显式选择。

## 延迟与复现

Ultra 5 的五次校准 worker 墙钟为 8.17–8.39 秒，MAX395 为 1.79–1.91 秒。
这包含加载和第一次运行，因此不将“约 1–2 秒小样本推理目标”描述为所有机器的首次总延迟。

## 正式入口与结果一致性

初版实现相关回归共 **593 项通过**，覆盖设备策略、配置原子写入、会话并发、MFR 尾批、模型预加载、
CLI、PDF 模型流程及资源生命周期；另有两项第三方弃用提示。wheel 构建成功，确认包含六张 PNG、
manifest、正式阈值及互斥的平台运行时依赖。

本机使用正式解析入口，分别在新进程中配置 `onnx_device=cpu` 和 `gpu`，
对 demo1+demo2 合并的 19 页 PDF 执行 basic + 强制 OCR：

- 两次均完成全部 19 页，Middle JSON 的 `pages` 数组完全一致，包含页面顺序、块结构、边界框、正文与公式。
- Markdown 文件逐字节一致，SHA256 为 `6fa409c5986b5207a4cadff8d106a063c977180758babe615fc5ce58ebd86b49`。
- GPU 路线实际使用 DML 的组件为 layout、rec、MFR；检测、表格和 MFR 不足 8 张的尾批使用 CPU。
- 完整结果、会话 provider 和比较记录保存在本轮输出目录的 `document-*-verified/` 与 `document-comparison.json`。

额外使用隔离配置文件验证真实进程生命周期：首次 `auto` 测速后写入 `gpu`，下一新进程
返回 `configured_gpu`，未重新测速，配置中的其他键保持不变。
本机首次自动选择约 20.57 秒，包括 UMA 设备分类与约 8.11 秒的测速 worker；
这不是单独的 rec 推理耗时，也不包含随后生产模型的加载。

发现逐张创建 D3D12 设备分类会使后续选择仍耗时约 12 秒后，已优化保存为 `gpu` 的路径：
利用 Windows 高性能排序，并以空 `ppDevice` 检查 D3D12 能力，避免重复创建分类设备。
本机该枚举约 0.11 秒，包含 ORT 导入和读取配置的完整选择约 0.33 秒，所选 LUID/编号不变。
首次 `auto` 仍执行 UMA 分类；旧 Windows 缺少高性能排序接口时保留分类以确保独显优先。
接口行为参见 [D3D12CreateDevice](https://learn.microsoft.com/en-us/windows/win32/api/d3d12/nf-d3d12-d3d12createdevice)。
